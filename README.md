# B站弹幕点歌机 + 直播排队

连接 B站直播间，观众发弹幕「**点歌 歌名**」自动搜歌 → 排队 → 播放；
发弹幕「**排队**」加入互动排队名单，送**粉丝团灯牌**可插队。

**点歌与排队深度融合在同一程序内**：

- 同一条 B站弹幕连接：点歌与排队共用监听，切直播间两边同时生效；
- 同一份 B站扫码登录：登录后观众完整昵称/uid 两个功能都能拿到；
- 同一个服务（8788）、同一个管理控制台（「直播排队」标签页）。

歌曲源可插拔（B站 / QQ音乐 / 酷狗 / 网易云 / 本地 / 演示），支持免费 + 扫码登录双模式，
并能识别平台只给「试听片段」的付费/会员歌曲。

> 第一次使用建议先看 [作者的话](作者的话.md)（含操作截图与几个常见注意事项）。
> 附带素材：[异环小吱直播边框](docs/素材/异环小吱_直播边框_厚_1920x1080.png)（1920×1080，OBS 图片源铺满画布即可套在直播画面外层）。

## 0. 版本记录

### v1.1.6（2026-10-24）

- **修「只发一条弹幕，日志里出现五六条」**：扫码成功那一刻，控制台在途的几个
  `/api/login/status` 请求会同时触发「用新凭据重连弹幕」，于是并发起了 5~6 个监听连接，
  每条弹幕被每个连接各收一份。现在重连过程用 `asyncio.Lock` 串行、
  配置+凭据没变直接跳过，并且同一次登录只处理一遍（`_consumed`）。
- 日志新增「弹幕监听已就绪 / 跳过重复重连」，一眼能看出是不是又起了多条连接。

### v1.1.5（2026-10-24）

- **修「明明登录了还是星号」**：B站扫码登录改成直连官方 passport 二维码接口
  （`/x/passport-login/web/qrcode/generate` + `/poll`），Cookie 从 `Set-Cookie` 和回调 URL 里取；
  旧实现用 bilibili_api 的 `get_credential()`，它可能返回**所有字段都是空串**的 Credential，
  序列化后是非空 JSON，于是界面显示“已登录”、弹幕却是匿名。
- **登录态判断加严**：B站 必须校验 `SESSDATA` 非空才算已登录；保存的无效登录态会明确提示
  “保存的登录态无效（没有 SESSDATA），请重新扫码”，而不是静静当匿名用。
- 扫码成功后详情里直接显示 uid。

### v1.1.4（2026-10-24）

- **弹幕去重**：同一条弹幕/礼物 10 秒内重复到达只处理一次（B站 重发、多连接各来一份时，日志会出现“一条变三条”）；
- **登录身份可见**：连接日志与体检页显示 `uid=xxx`，或明确写“匿名（昵称会脱敏成星号）”；
- 有 Cookie 但缺 `DedeUserID` 时打 WARNING —— 这就是“明明登录了、昵称还是星号”的典型原因；
- `_start_listener` 起新监听前先停旧监听，避免两个监听同时收消息。

### v1.1.3（2026-10-24）

修「第一次能用，后来忽然打不开 / OBS 一片空白」这一类静默失败：

- **启动失败必须出声**：单实例残留（上次没退干净）、端口 8788~8807 全被占、启动异常 → 弹系统消息框 + 写日志，不再一闪而过；
- **窗口标题带端口**：`B站弹幕点歌机 v1.1.3 · 端口 8789`，OBS 空白时第一眼就能比对是不是端口变了；
- **记录异常退出**：`cache/.running` 标记，崩溃/被强杀后下次启动会在日志和体检页明确写「上次没有正常退出」；
- **修**：`run.py` 末尾有两个 `if __name__ == "__main__"` 块，某些返回路径会让 `main()` 跑两次；
- 体检从 4 项扩到 5 项，新增「程序状态」（PID / 端口 / 上次退出情况）。

### v1.1.2（2026-10-24）


「稳一稳」版本：不加新玩法，只把日常会踩的坑补平。

- **启动体检**：控制台首页四行状态——弹幕连接 / B站登录 / 音源 / OBS 地址，红黄绿一眼看出哪项没配好；
- **连接看门狗**：连上了但 90 秒收不到任何数据（含心跳回包）→ 判定假连接、自动重连（B站偶发「TCP 还在但不推消息」，旧版只能干等）；

- **日志按天切分**：`jukebox.log` → 跨天自动切 `jukebox.log.2026-10-24`，保留 14 天；日志页加「每 5 秒自动刷新」；
- **exe 有了图标和版本号**：资源管理器/属性里能看到 v1.1.2 与产品名，不再是默认图标；
- 修：浏览器不自动打开（`IsUserAnAdmin()` 判断的是"你在不在管理员组"，管理员账号下永远 True；改用令牌 `TokenElevation`，提升运行时把 URL 交给 explorer 打开，不再弹 Edge 权限冲突）。

### v1.1.0（2026-10-24）

这一版主要解决「出事之后查不到原因」，以及几个会让人误以为「连不上直播间」的问题。

**新增：运行日志（最重要）**

- 所有日志同时写进 `cache\logs\jukebox.log`（2MB 滚动，保留 5 份），程序退出也不丢；
- 管理控制台新增「**运行日志**」标签页：直接看最近 400 行、一键下载、一键打开日志所在文件夹；

- 未捕获异常（含后台任务、子线程）也会写进日志，不再出现「闪退且什么都没留下」。

**修复：连不上直播间的几类原因**

- **弹幕认证加上 15 秒超时**：旧版 token 被风控时 B站什么都不回，界面永远停在「连接中…」；
  现在会明确告诉你「认证超时 / 被风控 / 房间号错误」并自动退避重连。
- **房间号校验**：切换 live 时先问 B站这个房间存不存在，填成「主播 UID」会被直接拦下并提示；
- 启动与每次连接都会把「房间号 / 是否有登录态 / 弹幕服务器地址 / 认证结果」写进日志；
- 重连退避在连接稳定 60 秒后复位（旧版只增不减，断一次要等 30 秒）；
- 「获取弹幕配置」失败时给出人话原因（-352 风控、-412 限流、网络/代理问题），不再静默重试。

**修复：其它**

- 关闭「重启后保留登录态」时，改任何设置都会把内存里的 Cookie 冲掉（表现为「刚扫码登录完，改个设置又要重登」）—— 已修；
- 「恢复默认设置」会显式清掉登录态（与按钮文案一致）；
- 音频流代理在异常路径上泄漏 HTTP 连接池 —— 已修；
- 恢复播放历史顺序反了（最新的一首跑到最后）—— 已修；
- 「立即播放」挤掉当前歌曲时没计数的排行权重 —— 已修；
- 日志里不再逐条记录每一条弹幕（热闹直播间会把文件刷爆），业务事件（点歌/排队/错误）仍然全记。

**界面**

- 侧栏显示版本号；支持用 `…/web/console.html#logs` 直接打开某个标签页。

**分发/运行环境（2026-10-24 实测撞上）**

- 新 exe 没签名，首次双击必被 SmartScreen 拦（程序还没启动，不是卡死）：「更多信息 → 仍要运行」；包内附 `启动.bat` 可自动 `Unblock-File` 后启动。
- 若报 `[PYI-####:ERROR] Could not create temporary directory!`：exe 所在目录带了 **Low 完整性标签**（DSH 工作区/某些沙箱会给整棵子树打 Low），低完整性进程写不了 `%TEMP%`。挪到普通目录（如 `D:\bili-jukebox\`）即可；或 `icacls "<目录>" /setintegritylevel (OI)(CI)M /T /C` 恢复成 Medium。

## 1. 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 一键启动（默认 mock 弹幕模式，端口 8788）
python run.py
```

启动后终端会打印页面地址，浏览器打开 **管理控制台** 即可使用：

| 页面 | 地址 | 用途 |
|---|---|---|
| 管理控制台 | http://127.0.0.1:8788/web/console.html | 本地操作全部功能（含「直播排队」标签页） |
| OBS 播放页 | http://127.0.0.1:8788/obs | 放进 OBS 浏览器源，黑胶唱片动画 |
| OBS 歌词页 | http://127.0.0.1:8788/stage | 放进 OBS 浏览器源，滚动歌词（支持透明背景 `?transparent=1`） |
| OBS 排队名单页 | http://127.0.0.1:8788/queue | 放进 OBS 浏览器源，竖版排队面板（透明背景） |

> 根路径 `/` 会自动跳转到管理控制台。
> **点歌功能默认关闭**：首次使用请到「设置」页点击「开启点歌」，观众弹幕点歌才会生效。
> 关闭启动它的命令行终端，程序会自动退出，不会在后台残留。

## 1.5 直播排队

观众在直播间发弹幕（口令可在 `config.yaml` 的 `live_queue.keywords` 配置，默认「排队」）：

| 行为 | 说明 |
|---|---|
| `排队` | 加入队列末尾；重复发送保持原位置，只更新内容 |
| `排队，轨外` | 入队并记录「要打的内容」（分隔符支持 ，；：、。— 与空格等） |
| 送「粉丝团灯牌」 | 已在队列 → 插队到第 1 位；不在队列 → 记 1 次待用资格，之后发「排队」时消耗并插队 |
| 「取消插队」开关 | 开启后灯牌既不插队也不记资格（控制台可切） |

管理控制台「直播排队」标签页支持：叫号「下一位」、手动加人/移位（`add-名字-位置`）、
删人（`del-序号`）、清空、口令/内容/礼物名配置（热生效）、
OBS 字号与面板/名单透明度调节、「开播自动清空」、本地测试（模拟排队/送礼）。

OBS 名单页特性：小吱主题的票据式竖版面板（2:3），上下装饰固定、中间条带随人数延伸，
第 1 位金色描边，人数超出时名单无缝循环滚动，后端断开时自动隐藏画面。

## 2. 两种弹幕模式

编辑 `config.yaml` 的 `danmaku.mode`（也可在控制台「直播间」面板切换）：

- **`mock`（默认）**：不连接 B站，用控制台里的「模拟弹幕」输入框注入弹幕，方便调试/演示。
- **`live`**：连接真实 B站直播间。设置 `room_id`（live.bilibili.com/ 后的数字）后启动即可自动监听弹幕。
  可选 `credential_file` 填 B站登录 Cookie JSON，提升风控通过率。

> 切换直播间：`POST /api/danmaku/reconnect {"mode":"live","room_id":12345}`。
> `room_id` 为空或非法会被拒绝（`mode=live` 必须有房间号）。

## 3. 点歌指令

观众在直播间（或控制台模拟弹幕）发送：

| 指令 | 说明 | 示例 |
|---|---|---|
| `点歌 歌名` | 搜歌并入队（前缀可配：`点歌/求歌/来首/我想听`） | `点歌 海阔天空` |
| `点歌 <源> 歌名` | 指定音源 | `点歌 qq 七里香`、`点歌 b站 晴天`、`点歌 网易云 晴天` |
| `切歌` / `下一首` / `skip` | 切歌（默认仅主播；开 `allow_user_skip` 后观众可切） | |
| `点歌列表` / `队列` | 查看当前队列 | |
| `点歌帮助` | 查看帮助文案 | |

源别名：`b站/bilibili/哔哩`、`qq/qq音乐/q音`、`酷狗/kugou`、`网易/网易云/netease`、

`本地/local`、`演示/demo/测试`。未启用的源会被拒绝并提示先去管理页打开。

**规则（可在控制台调整）**
- 同一用户点歌冷却 `user_cooldown_seconds`（默认 30s）
- 同一首歌重复点歌冷却 `song_cooldown_minutes`（默认 10min）
- 每人同时在队列上限 `max_per_user_queue`（默认 3）
- 队列总上限 `max_queue_length`、单首时长上限 `max_song_duration`、关键词黑名单 `blacklist`

## 4. 管理控制台功能

- **音源开关与排序**：勾选启用哪些源，拖动调整搜索优先级（未指定的源会智能按匹配度/播放量/收藏量排序选最优结果）。
- **扫码登录**：B站 / QQ / 酷狗 / 网易云 一键扫码，登录后播放付费/会员歌曲；Cookie 持久化，重启不丢失。
- **直播间**：切换 mock/live、设置房间号。
- **点歌规则**：冷却、队列上限、黑名单、是否允许观众切歌、是否保留播放列表等。
- **播放控制**：暂停/继续/拖动进度/切歌/置顶/调整顺序/移除。
- **热歌榜**：按点播次数自动统计 Top10。
- **模拟弹幕**：不连 B站也能完整测试全流程。

> 控制台所有修改只写入 `cache/settings.json`，**不会改动 `config.yaml`**；
> 点「恢复默认设置」即清空覆盖层回到 `config.yaml` 基线。

## 6.5 打包成单文件 exe（免装 Python 分享给别人）

已配好 PyInstaller，一条命令产出 `dist/bili-jukebox.exe`，**对方无需安装 Python**。

```bash
pip install pyinstaller
python -m PyInstaller build.spec --noconfirm   # 或双击 build.bat
```

产物 `dist/bili-jukebox.exe` 是单个文件，直接发给别人即可运行：

- 首次运行会在 **exe 同目录** 生成 `cache/`（`settings.json` 设置、排队记录、播放列表）与 `config.yaml`；
- `config.yaml` 就在 exe 旁边，**可以直接编辑**（改完重启生效），不用再动源码；
- 同一时间只允许一个实例：重复双击会直接打开已在运行的管理页，避免重复入队/双播；
- 建议把 exe 放到一个**有写入权限的普通文件夹**（如桌面、Downloads），不要放系统保护目录；
- 启动后控制台会打印页面地址；浏览器打开「管理控制台」即用。

> 资源打包说明：`web/` 与 `config.yaml` 由 `jukebox/config.py` 的 `_project_root()`
> 在运行时从 PyInstaller 解包目录（`sys._MEIPASS`）定位；可写缓存目录由 `app_data_dir()`
> 定位到 exe 同目录，保证设置持久化。

## 7. 配置说明（config.yaml）

`config.yaml` 位置：源码运行 → 项目根目录；exe 运行 → **exe 同目录**（首次运行自动生成）。

- `server.host`：默认 `127.0.0.1`（仅本机可访问）。
- `server.port`：**硬性 8788**，不要改。
- `danmaku.mode`：`mock` / `live`。
- `jukebox.request_enabled`：点歌总开关，默认 `false`，管理页「设置」可一键开启。
- `jukebox`：点歌前缀、冷却、队列上限、黑名单、保留播放列表等。
- `live_queue`：排队口令、可打内容关键词、优先礼物名、名单行数上限。
- `sources.active`：启用的音源及优先级顺序。
- `cache.search_ttl_minutes`：搜索结果缓存时长。

## 7.5 安全说明

- **默认只监听 127.0.0.1**：管理页、OBS 页面都只在本机可用，同网络的其他设备无法操作。
- 需要手机/平板遥控时，把 `server.host` 改成 `0.0.0.0` 后重启；此时同网络设备可打开管理页，**本程序没有登录密码**，请只在可信网络使用。
- `/api/settings` 不会返回 Cookie 明文（只标记是否已登录），避免凭据被其它程序读取。
- 所有写操作会校验请求来源：来自其它网站的跨站请求一律拒绝（403），WebSocket 同样校验。

## 7.6 运行日志（v1.1）

```
<exe 同目录>\cache\logs\jukebox.log      ← 当前日志（2MB 滚动）
<exe 同目录>\cache\logs\jukebox.log.1…5  ← 更早的 5 份
```

- 控制台「运行日志」标签页可以在线看、下载、打开文件夹，不用自己找路径；
- 启动参数、房间号校验、弹幕服务器地址、认证结果、重连原因、播放/点歌/排队事件、所有异常都会记进去；
- **每一行弹幕不记**（只在「弹幕日志」页看最近 100 条），避免热闹直播间把文件刷爆；
- 日志里的 Cookie/Token 会自动打码（`buvid3=***`、`SESSDATA=***`），**可以放心发给别人排错**。

> 报障请附：`jukebox.log` 一份 + 当时的操作（例如「切到 live 模式 → 输入房间号 xxx → 一直连接中」）。
> 只有截图没有日志时，作者基本只能猜。

## 8. 常见问题

- **双击 exe 后控制台一闪而过 / 自己关了**：
  - 已做两处保护：① 端口 8788 被占用时会**自动顺延到 8789/8790…**，不会再一启动就崩；
    ② 任何启动报错都会在黑窗口里**打印报错并提示「按 Enter 关闭」**，不会再无声消失。
  - 如果窗口里出现了红色报错，请把那段文字/截图发我。
  - 如果**完全没有任何窗口**（连一闪都没有），多半是 Windows 拦截了未签名的 exe：
    可右键 → 属性 → 解除锁定，或把 exe 加入杀软白名单后重试。
  - 若提示缺少运行库（极少），在联网环境下通常自动解决；仍可 `python run.py` 源码方式运行。
- **没声音 / 播放失败**：检查 OBS 播放页是否在前台、源是否联网、是否触发付费片段（看控制台提示）。
- **点歌搜不到**：换关键词（歌名/歌手），或换一个已启用的音源指定搜索。
- **live 模式一直「连接中…」/ 连不上直播间**（v1.1 已明确提示原因）：
  - 先看控制台右上角那行字，它会直接写原因；再看「运行日志」页；
  - `认证超时` = B站没给 token 或回包被风控 → 稍等几分钟再点「保存并重连」，或先扫码登录 B站；
  - `B站查不到直播间 xxx` = 房间号填错了，要填 `live.bilibili.com/` 后面的数字，**不是主播 UID**；
  - `未开播` 时能连上但收不到真实弹幕，属正常，可先用「模拟弹幕」验证功能；
  - 还不行就把 `cache\logs\jukebox.log` 发我。
- **live 模式收不到弹幕**：确认 `room_id` 正确、直播间正在直播、必要时填 `credential_file`。
- **想清空播放列表**：控制台清空队列 + 切歌；或关掉 `keep_state_on_exit` 后重启服务。
